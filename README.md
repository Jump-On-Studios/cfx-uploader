# CFX Uploader

CFX Uploader automates CFX Portal asset version uploads from GitHub releases.

It can be used in three ways:

- as a Node library, intended for server-side integrations such as a Nuxt webhook
- as an HTTP CLI, recommended for CI, VPS, and automation
- as a browser CLI, useful for debugging the CFX Portal UI flow

The HTTP flow still uses Puppeteer for CFX passkey authentication, then uploads through `portal-api.cfx.re`.

## Requirements

- Node.js `18+`
- npm
- a GitHub token with release download access
- a CFX passkey credential generated by this project

## Passkey Setup

Passkey registration is required before any upload can authenticate to CFX.

Run:

```bash
npm run register-passkey
```

A visible browser opens on the CFX forum security page. In the browser:

1. Sign in if prompted.
2. Open the security page if the login flow redirects elsewhere.
3. Click **Add passkey**.
4. Enter a passkey name and confirm.
5. Return to the terminal and press `Enter`.

The command writes:

```text
./passkey-credential.json
```

To replace an existing credential:

```bash
npm run register-passkey -- --force
```

`passkey-credential.json` contains private key material. Keep it secret. It is ignored by git and should only be used for local development.

## Resource Configuration

Each uploaded resource repository must contain `cfx_uploader.json` at its root:

```json
{
  "portalName": "jo_chest 2",
  "foldersToZip": ["jo_chest"]
}
```

Fields:

- `portalName`: exact CFX Portal asset name
- `foldersToZip`: folders from the release source ZIP to include in the final upload ZIP

The final ZIP filename is based on `foldersToZip[0]`.

## Library Usage

Recommended server-side usage:

```js
import { createUploader } from 'cfx-uploader';

const uploader = createUploader({
  githubToken: process.env.GITHUB_TOKEN,
  passkey: {
    credentialId: process.env.CFX_UPLOADER_CREDENTIAL_ID,
    rpId: process.env.CFX_UPLOADER_RP_ID,
    privateKey: process.env.CFX_UPLOADER_PRIVATE_KEY,
    userHandle: process.env.CFX_UPLOADER_USER_HANDLE,
    signCount: Number(process.env.CFX_UPLOADER_SIGN_COUNT),
  },
  headless: true,
  workDir: '/tmp/cfx-uploader',
});

const result = await uploader.upload({
  repository: payload.repository.full_name,
  releaseTag: payload.release?.tag_name,
});
```

Direct helper:

```js
import { upload } from 'cfx-uploader';

const result = await upload({
  repository: 'Jump-On-Studios/RedM-jo_chest',
  releaseTag: 'v1.1.2',
  githubToken: process.env.GITHUB_TOKEN,
  passkey: {
    credentialId: process.env.CFX_UPLOADER_CREDENTIAL_ID,
    rpId: process.env.CFX_UPLOADER_RP_ID,
    privateKey: process.env.CFX_UPLOADER_PRIVATE_KEY,
    userHandle: process.env.CFX_UPLOADER_USER_HANDLE,
    signCount: Number(process.env.CFX_UPLOADER_SIGN_COUNT),
  },
  headless: true,
});
```

The library returns a structured result on success:

```js
{
  success: true,
  mode: 'http',
  repository,
  releaseTag,
  resolvedReleaseTag,
  portalName,
  version,
  assetId,
  versionId
}
```

For VPS/Nuxt usage, store passkey fields as separate environment variables:

```env
GITHUB_TOKEN=...
CFX_UPLOADER_CREDENTIAL_ID=...
CFX_UPLOADER_RP_ID=forum.cfx.re
CFX_UPLOADER_PRIVATE_KEY=...
CFX_UPLOADER_USER_HANDLE=...
CFX_UPLOADER_SIGN_COUNT=1
```

The package also exports lower-level helpers:

```js
import { uploadHttp, uploadBrowser } from 'cfx-uploader';
```

These are mainly intended for advanced usage and CLI wrappers.

## CLI Usage

Install dependencies:

```bash
npm install
```

Create a local `.env`:

```env
GITHUB_TOKEN=your_github_token
```

Use `.env.example` as a template for all supported variables.

Local CLI runs use:

- `src/config/mock-config.js` for `githubRepository`
- `passkey-credential.json` for local passkey auth
- `cfx_uploader.json` from the downloaded release when present

### HTTP Mode

Recommended automation mode:

```bash
npm run orchestrate-http
```

Use a specific release tag:

```bash
npm run orchestrate-http -- --release-tag=v1.1.2
```

Show the browser during authentication:

```bash
npm run orchestrate-http -- --show-browser
```

### Browser Mode

Browser mode drives the full CFX Portal UI with Puppeteer. It is useful for debugging portal changes.

```bash
npm run orchestrate
```

Show the browser:

```bash
npm run orchestrate -- --show-browser
```

## Release Version Rules

Release tags can be written with or without a leading `v`.

Examples:

- `1.0.0`
- `v1.0.0`

If one form is requested and only the other exists, CFX Uploader tries the alternate form automatically.

After downloading the release, the resolved tag is compared with `fxmanifest.lua` `version`. The leading `v` is ignored, but all other differences fail before authentication or upload.
